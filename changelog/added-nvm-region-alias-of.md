Added an optional `NvmRegion::alias_of` field to describe "virtual" flash alias windows. When set, flash data staged for the region is transparently redirected to the canonical flash region starting at `alias_of` before any flash operation (init/erase/program/verify) runs, so the flash algorithm always executes at the address it expects. The GDB server also advertises such alias windows as flash at their own address, so `load` works against them.
