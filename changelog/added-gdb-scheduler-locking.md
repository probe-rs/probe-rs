The GDB server now implements GDB's "scheduler locking" (`set scheduler-locking on`): a resume that targets only specific threads runs just those cores and leaves the rest frozen, while a bare `continue` still resumes every core. This lets the `gdbstub` dependency be updated to 0.7.10, reverting the temporary 0.7.8 pin that was blocking the crash where the target did not implement `MultiThreadSchedulerLocking`.
